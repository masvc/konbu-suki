## 振り分けの基準

`npx tsx scripts/triage-rakuten.ts <判定JSON>` が機械的に分ける。

- `score >= 0.85` → 自動で書き換え
- `0.72 <= score < 0.85` → レビュー用 CSV
- 未一致 → 触らない

ただし 0.85 を超えていても、次の 2 つは CSV 送りにしている。

- **相手だけが複数個入り**（14 件）
- **価格が離れている**（7 件）

スコアだけでは弾けない誤りが実際にあったため。単品 360ml に対して
12 本入りケースが 0.85 で当たっていた。買いに行った人が別物を見ることになる。

## レビュー待ち 48 件の内訳

| 理由 | 件数 |
| --- | ---: |
| スコアが 0.85 未満 | 27 |
| 相手だけ複数個入り | 14 |
| 価格が離れている | 7 |

CSV には商品名・楽天側の商品名・価格・判定根拠が入っている。
目視で問題なければ、該当行を判定 JSON から拾って
`npx tsx scripts/match-rakuten.ts --apply <file> --write` で適用できる。

## 照合の仕組みで直したこと

- **検索語が具体的すぎて 0 件だった**。商品名をそのまま渡していたため
  「道南伝統食品 天然 利尻昆布 1等検 200g」のようになり、楽天の AND 検索で
  何も返らなかった。同じ語でも「利尻昆布」だけなら 2070 件ある。
  具体的な順に試し、候補が出た時点で打ち切るようにした。
- **セット商品に満点で当たっていた**。商品名が丸ごと含まれるため。
  「羅臼昆布300g」が「羅臼昆布300g + 本枯節粉60g のだしセット」に 1.00 で
  一致していた。相手だけがセットのときは減点する。
